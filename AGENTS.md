# ИИ-редколлегия → Telegram

Конвейер по докладу Павла Фёдорова «ИИ-редколлегия: как писать через нейронки
без слопа» (конференция «Контент, чтобы выжить в 2026», 01:55:52–02:32:22).
Семь скилов, каждый — отдельный репозиторий `github.com/beaverbeard/*` (MIT,
Родион Скрябин / рассылка «рИИдактор»), склонированы рядом в этой папке.

Цель: писать посты для Telegram-канала голосом конкретного человека, без
нейрослопа, с фактчеком — и публиковать через `publish_telegram.py`.

## Как это работает для агента (Codex / Claude Code)

Ни один из этих скилов не «идёт по проводам» автоматически — вы (агент) на
каждом шаге **открываете нужный `SKILL.md` и следуете его инструкциям**,
применяя их к тексту. В Claude Code эти папки дополнительно подключаются как
обычные skills (`.claude/skills/...`) и вызываются slash-командами; в Codex
такого автоподключения нет — читайте `SKILL.md` напрямую как инструкцию для
этого шага.

Карта скилов (путь → что делает → когда использовать):

| Скил | SKILL.md | Что делает |
|---|---|---|
| Виноградов | `vinogradov/SKILL.md` | Считает голос автора по 5–20 его текстам → `voice-{slug}/SKILL.md` |
| Бахтин | `bakhtin/.claude/skills/bakhtin/SKILL.md` | N агентов пишут черновик параллельно, компилируют лучшее |
| Чуковский | `chukovsky/.claude/skills/chukovsky/SKILL.md` | Смысл, структура, канцелярит, голос |
| Аграновский | `agranovsky/.claude/skills/agranovsky/SKILL.md` | Фактчек: «нет пруфа — выдумано», реальный веб-поиск |
| Слопотрон | `slopotron/.claude/skills/slopotron/SKILL.md` | ~100 признаков нейрослопа, кластерный принцип |
| Розенталь | `rozental/.claude/skills/rozental/SKILL.md` | Орфография, пунктуация, согласование |
| Мильчин | `milchin/.claude/skills/milchin/SKILL.md` (+ `milchin.py`) | Типографика — чистый Python-скрипт, 0 токенов LLM |

## Шаг 0 — голос (один раз на автора/канал)

Нужно 5–20 реальных текстов автора (посты, черновики, расшифровки).

```
Прочитай vinogradov/SKILL.md и проведи по нему интервью + анализ корпуса.
Результат: voice-{slug}/SKILL.md — положи его в drafts/voice/{slug}/SKILL.md.
```

Без этого шага Бахтин пишет нейтральным голосом — тоже рабочий вариант для
старта, но без личного отпечатка.

## Шаг 1 — черновик (Бахтин)

```
Прочитай bakhtin/.claude/skills/bakhtin/SKILL.md и его directions/tg-post.md.
Формат: tg-post. N=3 (баланс, см. README про стоимость: N=1 дёшево, N=5 —
максимум диверсити для важных постов). Если есть voice-профиль из шага 0 —
передай его агентам.
Материал: <тема / бриф / надиктовка>.
Сохрани результат в drafts/{slug}/00-draft.txt
```

Бахтин **только генерирует** — не финал, дальше обязательна вычитка.

## Шаг 2–6 — конвейер вычитки (порядок фиксирован)

**смысл → истина → детектор → буква → форма**

```
2. Прочитай chukovsky/.claude/skills/chukovsky/SKILL.md, режим Правка,
   жанровый режим "Голос" (личный тон Telegram-канала).
   drafts/{slug}/00-draft.txt → drafts/{slug}/01-chukovsky.txt

3. Прочитай agranovsky/.claude/skills/agranovsky/SKILL.md.
   ОБЯЗАТЕЛЕН, если в тексте есть числа/цитаты/факты (в tg-post обычно есть —
   Бахтину прямо запрещено выдумывать цифры, но иногда всё равно проскакивает).
   drafts/{slug}/01-chukovsky.txt → drafts/{slug}/02-agranovsky.txt

4. Прочитай slopotron/.claude/skills/slopotron/SKILL.md, режим Fix.
   Дай вместе с текстом исходный бриф/надиктовку как источник — включит
   проверку "что модель дописала сверх сказанного".
   drafts/{slug}/02-agranovsky.txt → drafts/{slug}/03-slopotron.txt

5. Прочитай rozental/.claude/skills/rozental/SKILL.md, режим Правка.
   drafts/{slug}/03-slopotron.txt → drafts/{slug}/04-rozental.txt

6. Типографика — ПОСЛЕДНИМ, иначе LLM-шаги 2-5 затрут NBSP/ёлочки.
   python3 milchin/.claude/skills/milchin/milchin.py \
     --file drafts/{slug}/04-rozental.txt --fix > drafts/{slug}/05-final.txt
```

## Шаг 6.5 — обложка (опционально)

Ни один из 7 скилов картинки не ищет — это отдельный скрипт `find_cover.py`
(royalty-free через Unsplash/Pexels, бесплатные ключи в `.env`, см.
`.env.example`). Двухшаговый, с человеком между поиском и скачиванием —
чтобы в канал не улетела случайная неподходящая картинка:

```bash
python3 find_cover.py --query "duolingo owl mascot marketing"   # только список, ничего не скачивает
python3 find_cover.py --query "duolingo owl mascot marketing" \
  --pick 2 --out drafts/{slug}/cover.jpg                         # скачивает выбранный номер + атрибуцию рядом
```

Запрос — по-английски (оба API так полнее ищут), 2-4 ключевых слова по теме
поста, не по голосу канала. Ни Unsplash, ни Pexels не требуют атрибуции по
лицензии, но скрипт всё равно кладёт `{cover.jpg}.attribution.txt` рядом —
на случай смены политики площадки или спора. Для чужих кадров (пресс-фото
компании, скриншот статьи) этот скрипт не годится — те тянуть только вручную,
с проверкой, что источник разрешает такое использование.

## Шаг 7 — проверка человеком (обязательный чекпоинт)

Автопубликация без взгляда автора — не по методике доклада («халтура на
входе — халтура на выходе», и никакой из скилов не заменяет финальное
решение автора: у Чуковского и Розенталя есть раздел «На решение автора» —
спорные места, которые скилы намеренно не трогают).

## Шаг 8 — публикация

```bash
cp .env.example .env   # один раз, вписать TELEGRAM_BOT_TOKEN и TELEGRAM_CHANNEL_ID
python3 publish_telegram.py --text-file drafts/{slug}/05-final.txt --dry-run   # сверить перед отправкой
python3 publish_telegram.py --text-file drafts/{slug}/05-final.txt            # реальная публикация
# с картинкой:
python3 publish_telegram.py --text-file drafts/{slug}/05-final.txt --photo drafts/{slug}/cover.jpg
```

`TELEGRAM_CHANNEL_ID` — `@username` публичного канала или числовой id
(`-100...`) приватного; бот должен быть добавлен в канал админом с правом
постить.

## Расход токенов (из README Бахтина)

Бахтин токеноёмкий по дизайну — N параллельных генераторов + служебные
проходы. Дешёвый черновик → N=1, рабочий → N=3, важный → N=5. Аграновский
дорог по веб-поиску (десятки запросов на лонгрид) — для коротких tg-постов
это терпимо, для лонгридов имеет смысл быстрый режим (только типы риска 1–4).

## Известные ограничения

- Все текстовые скилы (кроме Мильчина) — только под русский язык.
- `publish_telegram.py` не проверяет и не правит текст — только отправляет
  то, что вы ему дали. Проверка — задача шагов 1–7.
- Каждый `redkollegiya/<skill>/` — отдельный git-репозиторий (свой `.git/`).
  Если весь `redkollegiya/` кладётся в один новый репозиторий — либо убрать
  вложенные `.git/` (потеряется история апстрима), либо подключить как git
  submodules. Ничего не удалено автоматически — решение за вами.
